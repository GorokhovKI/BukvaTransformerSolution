# Следующие шаги (для пользователя)

User-условная модель реализована кодом (коммит `b31ca2f`, ветка `user-adaptation`), но НЕ обучена.
Обучение запускается вручную. Порядок действий:

## 0. Перегенерация признаков (обязательно после перехода на одну руку)

Модель теперь одноручная (`NUM_HANDS=1`, вход 126→63) — старые `features_data/*.npy`
(126 признаков) не подходят. Бэкап старого чекпойнта уже сделан (`best_model_bukva_base.pth`).

```bat
.venv\Scripts\activate
python preprocess.py
```

## 1. Бэкап базовой модели

`train.py` пишет в тот же файл `CHECKPOINT_PATH = "best_model_bukva.pth"` и перезапишет его.

```bat
copy best_model_bukva.pth best_model_bukva_base.pth
```

(Если копия `best_model_bukva_base.pth` уже существует — шаг можно пропустить.)

## 2. Обучение (~часы на CPU)

```bat
.venv\Scripts\activate
python train.py
```

- Словарь пользователей (135 чел.) создастся автоматически из `data/annotations.tsv`.
- Ранний стоп по валидационному weighted F1 (patience 20 эпох).
- Валидация всегда с `<unk>` — обучение контролируется на обобщение к неизвестным пользователям.
- Признаки должны быть перегенерированы под 63 фичи (шаг 0).

## 3. Оценка

```bat
python eval_user_conditioned.py
```

Покажет:
1. Официальный test с `<unk>` — ориентир: не хуже 91.21% (базовая модель).
2. Known users (cond vs `<unk>`) — ⚠️ завышено: сэмплы были в обучении.
3. Таблицу по пользователям: `acc(<unk>)`, `acc(cond)`, Δ, n.

## 4. Проверка демо (если есть камера)

```bat
python demo.py --user <имя_из_annotations>
```

Известный пользователь → его эмбеддинг; неизвестный/без ключа → `<unk>` + адаптер.

## 5. Решение по критериям плана (PLAN_USER_CONDITIONED.md, §5)

| Результат | Действие |
|---|---|
| Известные ≥ +1 п.п., test ≥ 91.0% | фича работает → мёрж `user-adaptation` в `master` |
| test с `<unk>` < 91.0% | настраивать обучение |
| Нейтрально | зафиксировать в спецификации, третий заход не делать |

## Примечания

- Оценка известных пользователей на train-сэмплах завышена (сэмплы были в обучении).
  Несмещённая цифра требует per-user holdout при обучении — не реализован, делается по запросу.
- Кодировка консоли Windows: при проблемах с выводом — `set PYTHONIOENCODING=utf-8`.
- После переобучения метрики базовой модели 91.21% недействительны (это двухручная модель) —
  новые цифры зафиксировать в `SPECIFICATION.md` §5.
