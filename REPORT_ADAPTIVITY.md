# Отчёт: персональная адаптация к пользователю

> Ветка `user-adaptation`, коммит `0dec723`. Дополняет `PLAN_ADAPTIVITY.md` (план и методика измерений — там).

## 1. Что сделано

| Файл | Изменение |
|---|---|
| `personalization.py` | `_to_window()`: любая последовательность → окно 80 кадров (center-crop/pad) + padding-маска; используется в `predict_logits()` и `fit()`. `load()` → `bool`. Guard на пустой вход в `calibrate_features()`. Буфер → `deque(maxlen=200)`. `torch.load(..., weights_only=True)` для профилей |
| `eval_adaptation.py` (новый) | Честное измерение на официальном test-сплите: 20 пользователей, адаптация на K=5 сэмплах каждого, оценка на остальных 560. Пер-пользовательская таблица base vs adapt |
| `demo.py` | `--user <имя>`: загрузка/создание профиля, псевдо-лейблы при conf ≥ 0.9, клавиша `F` — ручное подтверждение образца, refit каждые 5 новых сэмплов, автосохранение профиля. Фикс `torch.load(..., weights_only=False)` (падение на torch 2.8) |
| `PLAN_ADAPTIVITY.md` (новый) | План + измеренные результаты + риски + критерии приёмки |
| `.gitignore` (новый) | `__pycache__/`, `.idea/`, `profiles/` — чтобы артефакты не попадали в коммиты |

## 2. Результат

### Измерения (test-сплит, 560 сэмплов оценки, адаптация на 5 сэмплах/пользователя)

| Вариант | Точность | Вывод |
|---|---|---|
| База (без адаптации) | **0.904** | опорная точка |
| Адаптер, без калибровки | 0.902 | нейтрально (−1 сэмпл, шум) |
| Только калибровка признаков | 0.873 | **вредит (−3 п.п.)** |
| Калибровка + адаптер | 0.870–0.876 | вредит |
| Онлайн-псевдо-лейблы (seed 5 + conf≥0.9, refit каждые 5) | 0.900–0.904 | равно базе |

Дополнительно: K=10 → база 0.9065, адаптер 0.9022. K=20 → 0.9077 vs 0.9077 (ничья).
Пер-пользовательски (K=5): 16/20 без изменений, 1 лучше (+0.036), 3 хуже (−0.036).

**Главный вывод:** база (91.2% на test) обучена на 155 пользователях и уже покрывает
межпользовательскую вариацию. Few-shot адаптация её не улучшает и не ухудшает —
нейтральна в пределах шума. Калибровка признаков стабильно вредит.

### Верификация
- Smoke-тест полного цикла `fit → save → load → predict` на сэмплах разной длины (30/80/120 кадров) — OK.
- `eval_adaptation.py` запускается, цифры воспроизводимы.
- `demo.py` — проверены синтаксис и логика; с камерой не запускался (нет веб-камеры в окружении).

## 3. Что вырезано и почему

| Вырезано / отклонено | Почему |
|---|---|
| **Калибровка признаков** (feat_mean) — не вызывается в demo | Измеренно −3 п.п. Среднее по кадрам жеста — это смесь переходных поз, а не «нейтральная» поза пользователя. Метод оставлен в коде: пригодится, если появится режим снятия нейтрального кадра без жеста |
| **Автокалибровка в demo** (первые 60 кадров при старте) | Следствие того же измерения |
| **Bias-only адаптация** (только 33 параметра сдвига классов) | Испытана: 0.871–0.876 — не лучше, чем full-адаптер; отдельный код не заводим |
| **UI-строка статуса адаптации** (из плана) | Текст не влезал в бокс 350px без переделки интерфейса; статус выводится в консоль |
| **Порог псевдо-лейблов 0.8** (вместо 0.9) | Испытан: даёт больше лейблов (77% потока вместо 63%), но точность та же — оставлен 0.9 ради чистоты буфера |
| **Гиперпараметры fit** (10 шагов, lr 1e-4, l2 1e-1) | Испытаны: результат тот же, что у дефолта (30 шагов, lr 1e-3, l2 1e-2). Оставлены простые дефолты |
| **User-условная модель** (user_id-эмбеддинг в CLS, переобучение на 155 пользователях) | Это переобучение всей модели (~150 эпох, часы) без гарантии выигрыша — другая задача. Задокументирована как альтернатива в `PLAN_ADAPTIVITY.md`, не реализована |
| **Экспериментальные скрипты** `exp_adapt*.py` (3 шт.) | Разовые измерения; все цифры зафиксированы в `PLAN_ADAPTIVITY.md` |

## 4. Что оставлено и почему

| Оставлено | Почему |
|---|---|
| Residual-адаптер с **zero-init up-ветки** + **L2-якорь 1e-2** | Identity-старт: без профиля поведение = базе; деградация измеренно ≤ 0.2 п.п. — риск минимален |
| **Клавиша F** (ручное подтверждение) | Единственный механизм с гарантированной ценностью: пользователь исправляет ошибки модели. Test-сплит этого не моделирует — эффект проявится только на практике |
| **Профили на диске** (`profiles/<user>.pt`) | Накопление сэмплов между сессиями: чем дольше пользователь работает, тем больше данных, при этом буфер capped 200 → адаптация следует за свежими сэмплами |
| Адаптация в demo **опциональна** (`--user`) | Без флага поведение прежнее — нулевой риск для существующих пользователей demo |

## 5. Итог

Адаптация реализована в безопасном варианте: на тестовых данных она нейтральна (0.902 vs 0.904),
на практике даёт профили пользователей, накопление образцов и ручную коррекцию ошибок (F).
Калибровка отключена по измерениям. Если целью станет гарантированный рост метрики —
следующий шаг user-условная модель, а не дообучение на лету.
