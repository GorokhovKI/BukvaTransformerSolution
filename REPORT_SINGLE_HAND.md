# Одноручная модель: разбор результатов и проверка честности метрик

Дата: 06.11.2026. Чекпойнт: `best_model_bukva.pth` (эпоха 40, early stop на 60).

## 1. Короткий вывод

| Вопрос | Ответ |
|---|---|
| Результат 80.31% — честный? | **Да.** test совпадает с val один в один, утечки нет |
| Прежние 91.21% — честные? | **Да.** воспроизведены независимо: 91.30% на заново сгенерированных признаках |
| Почему упало на 11 п.п.? | **Баг выбора руки**: активная рука выбирается по «максимуму движения», и в ~25% клипов с двумя руками выбирается **висящая (нерабочая) рука** |

Деградация не про архитектуру и не про гиперпараметры — это ошибка предобработки.

## 2. Честность метрик

### Новая модель (одна рука, 63 признака)
- `best epoch=40`, `val_f1=0.8143`, `val_acc=80.31%`, `train_acc=89.01%`, gap **+8.7 п.п.**
  (к концу обучения gap растёт до +13.7 — переобучение).
- Независимый пересчёт по чекпойнту на признаках теста: **acc = 0.8031 (526/655)** — совпадает
  с val до 4-го знака. Совпадение val и test — признак корректной оценки без подгонки.
- Сплит чистый: 135 train-пользователей и 20 test-пользователей не пересекаются;
  дублей пар (пользователь, буква) нет; дублей путей нет.

### Прежняя модель (две руки, 126 признаков) — проверка подозрения
Признаки 126-мерного формата были перезаписаны новым препроцессингом, поэтому старая метрика
перепроверена «с нуля»: старый код предобработки (`git show 4643845^:preprocess.py`) прогнан
заново по всем 655 тестовым видео (2 руки, без flip), затем оценён старый чекпойнт:

```
БАЗОВАЯ модель (2 руки, без flip) на перегенерированных test-признаках: acc = 0.9130 (598/655)
```

Против заявленных 91.21% (602/660) — расхождение 0.09 п.п. на 5 отсеянных клипах.
**Метрика 91.21% воспроизводится → была честной.** Признаки сохранены в `features_legacy_test/`
(18 МБ) для повторных проверок.

## 3. Что пошло не так

### Причина №1 — выбор «активной руки» по движению (главная)

`preprocess.py`, `key()`: активная рука = максимум `_motion(...)`, при равенстве — правая.
В дактиле в кадр часто попадают **обе** руки: рабочая поднята к груди, вторая висит вдоль тела
и при ходьбе/перемещении тела двигается **сильнее**.

Замер на случайной выборке 60 тестовых клипов (3 на пользователя):

| Факт | Значение |
|---|---|
| клипов, где MediaPipe видит обе руки | 32/60 = 53% |
| правило «максимум движения» выбрало поднятую (рабочую) руку | 24/32 = **75%** |
| правило «предпочитать Right» (по handedness) | 19/32 = 59% (метки ненадёжны) |

То есть **каждый четвёртый клип с двумя руками кормит модель висящей рукой** ≈ 13% всего датасета.

Прямое подтверждение на клипах худшего тестового пользователя (`db573f94…`, acc 39.4%):
средняя y-координата запястья (0 = верх кадра):

| клип | motion Left / Right | выбрана | её wrist y |
|---|---|---|---|
| М | 609 / 246 | Left | **0.69** — висящая рука (рабочая: 0.49) |
| Щ | 618 / 275 | Left | **0.73** — висящая (рабочая: 0.47) |
| А | 366 / 132 | Left | **0.74** — висящая (рабочая: 0.37) |
| Ш | 94 / 386 | Right | 0.45 — рабочая (корректно) |

### Причина №2 — ненадёжные метки handedness

`mirror_x=(label == "Left")` применяется **по кадру**. MediaPipe на этих видео часто путается:
в клипе «М» 49 кадров, но 58 детекций «Left» и 35 «Right» — одна и та же рука получает разные
метки в разных кадрах. Итог: случайное зеркалирование x и «фантомное движение» (то самое, по
которому выбирается рука). Доля «переворотов» x между соседними кадрами мала (mean 0.008),
но именно они раздувают `_motion` до 600+.

### Причина №3 — потеря второй руки как информации

Базовая модель видела **оба** слота и могла сама решить, какой информативен. Новая видит один.
Самые большие потери F1 (old → new): **Ъ 0.92 → 0.46**, **У 1.00 → 0.64**, Ь 0.84 → 0.61,
А 0.97 → 0.79. Претензии к классам те же, что были у базовой (Ш/Щ), но добавились новые.

### Что НЕ является причиной (проверено)

- **Разная хиральность у пользователей** — нет: при зеркалировании x точность падает у всех
  (0.80 → 0.11), т.е. весь датасет в одной киральной системе; ни у одного из 135 train-пользователей
  зеркало не улучшает результат.
- **Дыры в кадрах (нули)** — не главное: клипы без дыр дают 61%, с дырами 1–30% — 90–92%
  (обратная зависимость объясняется тем, что висящая рука видна в кадре постоянно).
- **Утечка/подгонка** — нет (см. §2).
- **User-cond** — работает: на train-сэмплах эмбеддинг пользователя даёт 91.2% против 88.7% с `<unk>`;
  на тесте он не участвует (`<unk>`), на метрику не влияет.

## 4. Что делать

Вариант A (рекомендуется) — **вернуть два слота, но с детерминированным порядком**:
слот 0 = рука выше (меньше средняя y запястья), слот 1 = вторая; вход снова 126.
Выбор руки исчезает как класс ошибок, модель видит обе руки (как базовая с 91.2%),
но без случайного порядка слотов. Сохранить selfie-flip (он выравнивает train и demo).

Вариант B (минимальная правка, остаётся 63 признака) — выбирать руку по **положению**
(самая высокая), а не по движению; handedness-зеркалирование делать один раз на видео
(голосование по кадрам), а не покадрово. Риск: у сидящих за столом обе руки на одной высоте.

В обоих случаях нужен повторный `preprocess.py` (≈4 000 видео) и переобучение.

Разовые артефакты диагностики: `_legacy_preprocess.py`, `_legacy_run.py`, `_diag_select.py`,
`features_legacy_test/`, `_diag_frames/` — можно удалить после решения.
