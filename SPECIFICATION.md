# BukvaTransformerSolution — Спецификация проекта

> Назначение документа: единый источник правды для будущей разработки. Фиксирует назначение,
> архитектуру, данные, модель, достигнутые метрики и известные риски. Обновлять при каждом
> значимом изменении кода или данных.

---

## 1. Назначение проекта

Распознавание **русской дактильной азбуки** (жестового алфавита РЖЯ) по видеопотоку.

- Вход: видеокадры (веб-камера или файл `.mp4`).
- Выход: буква русского алфавита `А`–`Я` (33 класса).
- Применение: субтитры в реальном времени для жестового общения (см. `demo.py`),
  экспорт модели в Unity (`rsl_dactyl.onnx`), персонализация под конкретного пользователя (`personalization.py`).

Ключевые артефакты:
| Файл | Роль |
|---|---|
| `best_model_bukva.pth` | Лучший чекпойнт (эпоха 93, F1≈0.9126) |
| `rsl_dactyl.onnx` | ONNX-экспорт для Unity (opset 17) |
| `rsl_dactyl_config.json` | Рантайм-конфиг ONNX-модели (вход/выход/классы/нормализация) |
| `features_data/` | Извлечённые признаки (`.npy`) + `metadata.npy` |
| `data/original/`, `data/trimmed/` | Исходные и обрезанные видео |

## 2. Данные

- Аннотации: `data/annotations.tsv` (таб-разделённый). Колонки:
  `attachment_id, user_id, text, begin, end, height, width, train, length`.
- **3 862** размеченных клипа, **155** уникальных пользователей.
- **34** метки: 33 буквы русского алфавита + служебный класс **`no_event`** (жест не распознан / нет жеста).
- Официальное разбиение (`train` колонка):
  - train = **3 182** (≈82%)
  - test  = **680** (≈18%), сбалансированный: **по 20 сэмплов на каждый из 34 классов**.
- Классы букв по ~101–125 клипов, из них 20 в test (у букв test = 33×20 = **660**).
- Видео: `data/original/` = 3 757 файлов, `data/trimmed/` = 3 862 файла (обрезка по `begin`–`end`).

> ⚠️ Класс `no_event` **отбрасывается** в `preprocess.py`, т.к. отсутствует в `CLASSES`
> (там только 33 буквы). Для реального времени `no_event` — это полезный rejection-класс,
> см. раздел «Риски».

## 3. Пайплайн

```
data/trimmed/*.mp4 ──► preprocess.py ──► features_data/*.npy + metadata.npy
                                              │
                                              ▼
                                       train.py ──► best_model_bukva.pth + results/
                                              │
                        ┌─────────────────────┼─────────────────────┐
                        ▼                     ▼                     ▼
                  demo.py (realtime)   pth_to_onnx.py         personalization.py
                                       (→ rsl_dactyl.onnx)    (→ profiles/*.pt)
```

### 3.1 `preprocess.py` — извлечение признаков
- MediaPipe Hands (`min_detection_confidence=0.5`, `min_tracking_confidence=0.5`,
  `max_num_hands=NUM_HANDS=2`).
- **Два слота рук**: кадр → тензор `[2 руки × 21 ландмарк × 3 (x,y,z)] = 126` чисел.
  Дактиль одноручный, но вторая рука часто в кадре; выбор «активной» руки по движению ошибался
  (см. `REPORT_SINGLE_HAND.md`), поэтому слоты детерминированы: **слот 0 — самая высокая рука
  в кадре** (в дактиле это рабочая), слот 1 — вторая (`_hand_features()`).
- Канонизация: selfie-ориентация `cv2.flip(frame,1)` (как в demo, устраняет train/serve skew).
  Метки `multi_handedness` для привязки/зеркалирования НЕ используются — MediaPipe путает
  Left/Right между кадрами, что даёт скачки координат и ложное «движение».
- Нормализация руки в `normalize_landmarks()`:
  1. центр в запястье (ландмарк 0) → `coords - wrist`;
  2. масштаб = норма вектора до ландмарка 9 (MCP среднего пальца);
  3. деление на масштаб, clip в `[-5.0, 5.0]`, flatten.
- Кадры без рук заполняются нулями — временная структура сохраняется (важно для динамических Ё, Й).
- Фильтр: видео с >50% нулевых кадров (рука не найдена) отбрасывается.
- Распараллеливание: `ProcessPoolExecutor` (отдельный экземпляр `Hands` на воркер — требование MediaPipe).
- Результат: `features_data/<id>.npy` (форма `[T, 126]`) + `features_data/metadata.npy`
  (`paths, labels, is_train, label_map`). Train-часть перемешивается, test — нет.

### 3.2 `train.py` — обучение
- `SignDataset`: загрузка `.npy`, аугментация (гаусс-шум σ=0.005, масштаб ×[0.9, 1.1]);
  обрезка по центру / паддинг до `SEQUENCE_LENGTH=80` + булева padding-маска;
  возвращает `(features, label, mask, user_idx)`.
- **User-условность**: словарь `user_id→idx` строится из `data/annotations.tsv` только по train-клипам
  (`load_user_maps`); assert пересечения пользователей train/test пусто (нет утечки); train-сэмплы
  получают `user_idx` своего пользователя, val — всегда 0 (`<unk>`, оценка обобщения на неизвестных).
  Без annotations.tsv → `user_dim=0`, поведение как раньше.
- Лосс: `CrossEntropyLoss(weight=class_weights, label_smoothing=0.1)` (классовые веса через `bincount`).
- Оптимизатор: `AdamW`, weight decay 1e-2 только для ненормирующих параметров
  (`norm`, `bias`, `cls_token` → decay 0).
- Шедулер: `OneCycleLR` (pct_start=0.1, cos, div_factor=10, final_div_factor=100).
- Gradient clipping: `max_norm=1.0`. Early stopping: `patience=20` по **weighted F1** на валидации.
- Чекпойнт сохраняет: `model_state_dict, model_config, epoch, best_f1, user_vocab`.
- Результаты: `results/training_history.json`, `results/evaluation_history.json`,
  `results/classification_report.txt`, 15 PNG (`plot.py`).

### 3.3 `demo.py` — реальное время
- Веб-камера `cv2.VideoCapture(1)` (⚠️ индекс захардкожен), зеркалирование кадра.
- Одна рука: канонизация как в `preprocess.py` (handedness → привязка, Left зеркалится,
  предпочтение правой при равенстве).
- Скользящее окно `deque(maxlen=80)`, инференс при ≥40 кадрах.
- `SubtitleManager`: буква фиксируется после `STABILITY_FRAMES=40` одинаковых предсказаний
  при уверенности `CONFIDENCE_THRESH=0.70`.
- Управление: `Q` выход, `SPACE` пробел, `BACKSPACE` удалить символ, `C` очистить.
- `--user <имя>`: если чекпойнт содержит `user_vocab` и имя в нём — инференс с эмбеддингом
  этого пользователя (user-cond), иначе `<unk>` + адаптер (`personalization.py`) может дообучиться.

### 3.4 `pth_to_onnx.py` — экспорт для Unity
- `InferenceWrapper`: вход `[1, 80, 126]`, **без padding-маски** (Unity заполняет окно
  80 реальными кадрами). Выход `[1, 33]` = logits.
- `torch.onnx.export` opset **17**, `do_constant_folding=True`.
- User-cond: экспорт без `user_idx` → модель сама подставляет `<unk>` (индекс 0) — ONNX
  побайтово совместим с обоими типами чекпойнтов, изменений в `pth_to_onnx.py` не требуется.
- Проверка эквивалентности PyTorch↔ONNX через `onnxruntime` (top-1 класс и max |Δlogits|).
- Пишет `rsl_dactyl_config.json` (input/output имена, форма, классы, параметры нормализации).

### 3.5 `personalization.py` — персональная адаптация (ветка `user-adaptation`)
- База замораживается. `UserAdapter`: `down(128→16) → GELU → up(16→128)` (zero-init up-ветки ⇒
  identity-старт: без профиля поведение = базе) + обучаемый `bias(33)`.
  Residual: `emb + adapter(emb)`, logits = `classify(...) + bias`.
- `_to_window()`: любая последовательность → окно 80 кадров (center-crop/pad) + padding-маска;
  используется в `predict_logits()` и `fit()`.
- `fit()`: AdamW lr=1e-3, L2-якорь 1e-2, label_smoothing 0.1, 30 шагов. Буфер `deque(maxlen=200)`.
- `load()` → bool. Профили: `profiles/<user>.pt` + `profiles/<user>_mean.npy`.
- Калибровка (`feat_mean`) реализована, но НЕ вызывается: измеренно вредит (−3 п.п., см. PLAN_ADAPTIVITY.md).
- `demo.py --user <имя>`: псевдо-лейблы (conf ≥ 0.9 при фиксации буквы), клавиша F — ручное
  подтверждение образца, refit каждые 5 сэмплов, автосохранение профиля.
- Измерено (test-сплит, K=5): база 0.904 vs адаптер 0.902 — нейтрально.
  Детали: `PLAN_ADAPTIVITY.md`, `REPORT_ADAPTIVITY.md`; измерение — `eval_adaptation.py`.
- `PersonalizedModel.user_idx` (None по умолчанию): пробрасывается в `embed()` базы — адаптер
  совместим с user-условной моделью.

### 3.7 `eval_user_conditioned.py` — оценка user-условной модели
- Работает с обоими чекпойнтами: `user_dim=0` → метрики теста + подсказка; `user_dim>0` →
  три цифры: (1) официальный test с `<unk>` — несмещённая проверка против 91.21%;
  (2) known users: train-сэмплы cond vs `<unk>` (⚠️ завышено — сэмплы были в обучении);
  (3) таблица по пользователям: `acc(<unk>)`, `acc(cond)`, Δ, n.

### 3.6 `model_adapter.py` — мобильный экспорт
- `torch.jit.script` + `mobile_optimizer.optimize_for_mobile` → `.ptl` (Lite Interpreter).
- Опциональная dynamic quantization int8 для `Linear` (по умолчанию выключена).

## 4. Архитектура модели (`model.py`)

`SignLanguageTransformer`:

1. **TemporalStem**: конкатенация кадров и их межкадровой дельты (`delta`), линейная проекция
   `input_size*2 → hidden`, depthwise Conv1d(kernel=5, groups=hidden) + pointwise Conv1d,
   LayerNorm + GELU + Dropout.
2. **Позиционное кодирование**: синусоидальное (max_len = sequence_length+1 под CLS).
3. **CLS-токен**: `nn.Parameter`, `trunc_normal_(std=0.02)` (не нулевая инициализация — избегает
   симметричного градиента через головы внимания).
4. **Энкодер**: 2 блока `TransformerBlock` (`MultiheadAttention` + FFN `hidden→4·hidden→hidden`, pre-norm).
5. **Голова**: `LayerNorm → Linear(128→128) → GELU → Dropout → Linear(128→33)`.
6. Классификация по позиции CLS (`x[:, 0]`).
7. **User-cond** (опционально, `ModelConfig.user_dim>0`): `Embedding(user_dim, 128, padding_idx=0)` —
   обучаемый эмбеддинг пользователя, прибавляется к CLS-токену перед энкодером (`_prepend_cls`).
   Индекс 0 = `<unk>` (`padding_idx=0` — нулевой вклад и не обучается ⇒ для неизвестных поведение = базовой
   модели; инициализация только строк 1..), `user_idx=None` ⇒ `<unk>`.
   `user_dim=0` — эмбеддинга нет, поведение/чекпойнты побайтово совместимы с базовой моделью.

Гиперпараметры (`constants.py`):
```
SEQUENCE_LENGTH=80  NUM_LANDMARKS=21  NUM_HANDS=2  INPUT_SIZE=126
HIDDEN_SIZE=128  NUM_LAYERS=2  NUM_HEADS=4  DROPOUT=0.3
BATCH_SIZE=16  LEARNING_RATE=1e-4  EPOCHS=150
ff_multiplier=4  temporal_kernel_size=5
```

**Размер**: 467 617 параметров ≈ **1.82 МБ** (две руки).

## 5. Достигнутые результаты

**Текущая модель** (два слота, детерминированный порядок, user-cond): Top-1 **89.0 ± 1.2%** —
это плато валидации (эпохи 20–90 держатся на 87.5–90.2%, колебания в пределах биномиального шума
на 660 клипах); лучшая эпоха по F1 даёт 90.15% (прогон `EPOCHS=90`) / 90.61% (прогон `EPOCHS=150`),
но это смещение выбора эпохи: валидация совпадает с тестом (те же 20 пользователей).
46% ошибок — 4 пары минимально различающихся букв: М→Т (11), Щ→Ш (10), Л→П (5), Ш→Щ (4).

## 7. Риски и известные проблемы (⚠️ важно для будущей разработки)

### 7.1 ИСПРАВЛЕНО: сломанный `forward()` в рабочей копии `model.py`
Раньше `return self.head(x[:, 0])` стоял **ДО** цикла энкодера (энкодер не выполнялся).
**Исправлено** (ветка `head_fix`, перенесено после цикла энкодера; теперь `forward()`/`embed()`
идут через `_prepend_cls`). Артефакты `best_model_bukva.pth` (июнь) и `rsl_dactyl.onnx` (сентябрь)
корректны, т.к. созданы до регрессии.

### 7.2 Класс `no_event` не используется
`CLASSES` содержит только 33 буквы; `no_event` (105 клипов) отбрасывается в `preprocess.py`.
Для продакшена realtime-системы это потерянный rejection-сигнал («жест не распознан / нет руки»).

### 7.3 Захардкоженные значения
- `demo.py`: `cv2.VideoCapture(1)` — индекс камеры; шрифт `/usr/share/fonts/...` — путь Linux,
  на Windows fallback-шрифт может не отрисовать кириллицу.
- Пути/константы частично в `constants.py`, частично захардкожены в модулях (напр. `CHECKPOINT_PATH`
  в `model_adapter.py`, `demo.py`).

### 7.4 Персональная адаптация и user-условность — ограничения (замерено)
- Few-shot адаптация (5 сэмплов) на официальном test-сплите нейтральна: 0.902 vs база 0.904.
- Калибровка признаков вредит (−3 п.п.) — не вызывается в demo.
- Практическая ценность адаптера — накопление сэмплов между сессиями и ручная коррекция (клавиша F),
  чего test-метрика не моделирует.
- User-условная модель реализована кодом, но **НЕ обучена** (P2 плана): обучение `python train.py`,
  оценка `python eval_user_conditioned.py`. Критерий приёмки: известные ≥ +1 п.п., test с `<unk>` ≥ 91.0%.
  ⚠️ Оценка known users на train-сэмплах завышена (сэмплы были в обучении) — для несмещённой
  цифры нужен per-user holdout при обучении (пока не реализован).

### 7.5 Требования неполны
`requirements.txt` не включает `onnx`, `onnxruntime`, `scikit-learn`, `seaborn` — они нужны
для `pth_to_onnx.py` и `plot.py`/`train.py`.

### 7.6 Перегенерация признаков после смены схемы слотов
Вход снова 126 признаков (две руки), но **порядок слотов другой**: раньше MediaPipe отдавал руки
в произвольном порядке, теперь слот 0 — самая высокая рука. Старые `features_data/*.npy`
непригодны (другой порядок слотов и selfie-flip):
- Порядок: `python preprocess.py` → `python train.py` → `eval_user_conditioned.py` → `pth_to_onnx.py`.
- Чекпойнт с `input_size=63` (одноручный эксперимент) не совместим — `demo.py` это детектирует.
- Бэкап двухручной базовой модели — `best_model_bukva_base.pth`.
- Метрика 91.21% относится к старой схеме слотов; одноручный эксперимент дал 80.31%
  (разбор: `REPORT_SINGLE_HAND.md`). После переобучения зафиксировать метрику в §5.

## 8. Быстрый старт

```bash
# активация venv
.venv/Scripts/activate            # Windows

# 1) признаки (при отсутствии features_data/metadata.npy)
python preprocess.py

# 2) обучение
python train.py

# 3) реальное время
python demo.py

# 4) экспорт ONNX
python pth_to_onnx.py

# 5) мобильный экспорт
python model_adapter.py
```

> Перед первым запуском после перехода на одноручную модель — см. §7.6 (перегенерация признаков
> и переобучение). Бэкап старого чекпойнта уже сделан (`best_model_bukva_base.pth`).
